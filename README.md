## 구현할 기능 목록들

### 1. 사용자로부터 로또 구입 금액을 입력받는다.

- [ ] 사용자에게 구입 금액 입력 메시지를 출력한다.
- [ ] 사용자로부터 구입 금액을 입력받는다.

예외

- [x] 입력이 `null`/빈 문자열/공백만 → 예외
- [x] 숫자가 아님(문자,소수점 등 포함) → 예외
- [x] 정수 범위 초과(오버플로우) → 예외
- [x] 0 또는 음수 → 예외
- [x] 1000원으로 나누어떨어지지 않음 → 예외

---

### 2. 구입 금액을 기준으로 발행할 로또 장수를 계산한다.

- [ ] 구입 금액 ÷ 1000 = 발행 장수로 계산한다.
- [ ] 발행 장수가 1장 이상인지 확인한다.

예외

- [ ] 발행 장수가 0장(금액 < 1000) → 예외

---

### 3. 로또를 발행한다(장수만큼).

- [ ] 각 로또는 `중복 없는 6개 번호`로 구성한다.
- [ ] 각 번호는 `1~45 범위`를 만족한다.
- [ ] 로또 번호는 `오름차순 정렬된 상태`로 보관/출력한다.
- [ ] 발행한 전체 로또 목록을 유지한다.

예외

- [ ] 번호 개수가 6개가 아님 → 예외
- [ ] 범위(1~45) 위반 → 예외
- [ ] 번호 중복 존재 → 예외

---

### 4. 발행 결과를 출력한다.

- [ ] `N개를 구매했습니다.`를 출력한다.
- [ ] 각 로또의 번호를 한 줄에 하나씩, `오름차순`으로 출력한다.

예외

- [ ] 출력 형식 불일치(대괄호, 쉼표/공백, 개행 위치 등) → 예외

---

### 5. 사용자로부터 당첨 번호 6개를 입력받는다.

- [ ] 당첨 번호 입력 메시지를 출력한다.
- [ ] 쉼표(,) 기준으로 구분된 문자열을 입력받는다.
- [ ] 각 토큰의 양끝 공백을 제거해 정규화한다.

예외

- [ ] 입력이 `null`/빈 문자열/공백만 → 예외
- [ ] 쉼표 외 구분자 사용 → 예외
- [ ] 연속 쉼표로 인한 빈 토큰(`",,"`) 또는 시작/끝 쉼표 → 예외
- [ ] 숫자가 아님 → 예외
- [ ] 숫자 개수가 6개가 아님 → 예외
- [ ] 범위(1~45) 위반 → 예외
- [ ] 중복 번호 존재 → 예외

---

### 6. 사용자로부터 보너스 번호 1개를 입력받는다.

- [ ] 보너스 번호 입력 메시지를 출력한다.
- [ ] 입력을 정수로 파싱하고 정규화한다.

예외

- [ ] 입력이 `null`/빈 문자열/공백만 → 예외
- [ ] 숫자가 아님 → 예외
- [ ] 범위(1~45) 위반 → 예외
- [ ] `당첨 번호 6개와 중복됨` → 예외

---

### 7. 당첨 결과를 산출한다.

- [ ] 구매한 각 로또와 당첨 번호를 비교해 `일치 개수`를 계산한다.
- [ ] `보너스 번호 일치 여부`를 계산한다.
- [ ] 아래 규칙으로 등수를 판정한다.

  - 1등: 6개 일치 (2,000,000,000원)
  - 2등: 5개 + 보너스 일치 (30,000,000원)
  - 3등: 5개 일치 (1,500,000원)
  - 4등: 4개 일치 (50,000원)
  - 5등: 3개 일치 (5,000원)
  - 그 외: 꽝(집계 제외)

- [ ] 등수별 `당첨 개수`를 집계한다.

예외

- [ ] 구매 목록이 비어 있음(앞선 단계에서 방어되는 게 일반적) → 예외/빈 결과 처리
- [ ] 금액 합산 시 정수 범위 문제(오버플로우) → 예외

---

### 8. 당첨 통계와 총 수익률을 출력한다.

- [ ] 등수별 결과를 요구 형식대로 출력한다.

  - `3개 일치 (5,000원) - N개`
  - `4개 일치 (50,000원) - N개`
  - `5개 일치 (1,500,000원) - N개`
  - `5개 일치, 보너스 볼 일치 (30,000,000원) - N개`
  - `6개 일치 (2,000,000,000원) - N개`

- [ ] 총 수익률 = `(총 당첨금 / 총 구매금액) * 100`을 계산한다.
- [ ] `소수점 둘째 자리 반올림`하여 `%` 형식으로 출력한다. (예: `62.5%`)

예외

- [ ] 0으로 나눔(구입 금액 0) → 예외
- [ ] 출력 형식 불일치(자리수,반올림 규칙,문구) → 예외

---

### 9. 예외 처리 및 재입력 정책

- [ ] 각 단계에서 검증 실패 시 `IllegalArgumentException`을 발생시키고, 메시지는 `[ERROR]`로 시작한다.
- [ ] 에러 출력 후 해당 단계부터 다시 입력을 받는다. (앞선 정상 단계는 유지)
- [ ] 불필요한 추가 출력 없이 정책에 맞게 흐름을 이어간다.

예외

- [ ] `[ERROR]` 접두 미준수 → 포맷 위반
- [ ] `System.exit()`로 강제 종료 → 금지

### 10. TDD 목록

### 1) 구입 금액 입력

- [x] `빈 문자열`을 입력하면 예외가 발생한다.
- [x] `공백만 있는 문자열`을 입력하면 예외가 발생한다.
- [x] `문자/기호가 섞인 입력`은 예외가 발생한다.
- [x] `정수 범위를 초과하는 입력`은 예외가 발생한다.
- [x] `양의 정수 & 1000원 단위 금액` 를 입력하면 발행 가능한 상태가 된다.
- [x] `1000원으로 나누어떨어지지 않는 금액`은 예외가 발생한다.

### 2) 발행 장수 계산

- [ ] `금액이 999원 이하`면 발행 장수는 0이 되어 예외가 발생한다.
- [ ] `1000원 단위`로 나눈 몫이 발행장수가 되며 나머지는 없어야 한다.

### 3) 로또 발행(한 장)

- [ ] `번호가 6개가 아닌 결과`가 생성되면 예외가 발생한다.
- [ ] `중복 번호가 포함된 결과`가 생성되면 예외가 발생한다.
- [ ] `범위(1~45) 밖 번호가 포함된 결과`가 생성되면 예외가 발생한다.
- [ ] `무작위로 얻은 6개 번호`는 오름차순으로 정렬된 상태로 보관된다.

### 4) 발행 결과(여러 장)

- [ ] `요청한 장수 = 실제 발행 장수`가 일치한다.
- [ ] `각 장의 번호가 6개,중복 없음,범위 만족,오름차순`을 모두 충족한다.
- [ ] `0장을 요청`하면 빈 결과가 나온다.

### 5) 당첨 번호 입력(쉼표 구분 6개)

- [ ] `빈 문자열/공백만`은 예외가 발생한다.
- [ ] `쉼표 외의 구분자 사용`은 예외가 발생한다.
- [ ] `연속 쉼표(빈 토큰)` 또는 `시작/끝이 쉼표`면 예외가 발생한다.
- [ ] `숫자가 아닌 토큰`이 포함되면 예외가 발생한다.
- [ ] `숫자 개수가 6개가 아니면` 예외가 발생한다.
- [ ] `범위(1~45) 위반 번호`가 있으면 예외가 발생한다.
- [ ] `중복 번호`가 있으면 예외가 발생한다.
- [ ] `토큰마다 앞뒤 공백이 있어도` 정상적으로 처리된다.

### 6) 보너스 번호 입력(1개)

- [ ] `빈 문자열/공백만`은 예외가 발생한다.
- [ ] `숫자가 아닌 값`은 예외가 발생한다.
- [ ] `범위(1~45) 위반`이면 예외가 발생한다.
- [ ] `당첨 번호 6개와 중복`이면 예외가 발생한다.
- [ ] `정상 입력`이면 당첨 번호와 결합 가능한 상태가 된다.

### 7) 당첨 결과 산출(등수 판정)

- [ ] `6개 일치`면 1등으로 판정된다(상금 2,000,000,000).
- [ ] `5개 + 보너스 일치`면 2등으로 판정된다(상금 30,000,000).
- [ ] `5개만 일치`면 3등으로 판정된다(상금 1,500,000).
- [ ] `4개 일치`면 4등으로 판정된다(상금 50,000).
- [ ] `3개 일치`면 5등으로 판정된다(상금 5,000).
- [ ] `그 외(0~2개)`는 꽝으로 분류되어 집계에서 제외된다.
- [ ] `여러 장을 동시에 평가`하면 등수별 개수가 정확히 집계된다.
- [ ] `총 상금 합계`가 정확히 계산된다(오버플로우 없이).

### 8) 수익률 계산

- [ ] `총 상금 / 총 구입 금액 × 100`으로 계산된 수익률이 정확하다.
- [ ] `소수점 둘째 자리 반올림` 규칙이 지켜진다(예: 62.5%).

### 9) 예외 처리 및 재입력 흐름

- [ ] `각 단계의 검증 실패` 시 `[ERROR]`로 시작하는 메시지가 출력된다.
- [ ] `오류가 난 단계부터 재입력`이 이뤄지고, 이전 정상 단계는 유지된다.
- [ ] `강제 종료 호출 없이` 전체 플로우가 정상적으로 이어진다.
- [ ] `불필요한 추가 출력 없이` 요구 형식을 그대로 따른다.
